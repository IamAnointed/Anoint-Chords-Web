# Anoint Chords — Website update + Drive Excel importer

## What's included
- `public/index.html`: Adds per-section lyrics/notes, JSON file picker, duplicate-title skipping, SOURCE chart support.
- `firestore.rules`: Public song viewing; only Super Admin, initial Admin and approved admins can write; secure `adminRequests` approval workflow.
- `import-tools/convert_drive_excels.py`: Converts downloaded `.xlsx` files to `songs-import.json` (SOURCE columns only).

## IMPORTANT
The 253 Google Drive source files are **NOT included in this ZIP** and have **NOT been imported into Firestore**. The converter needs local copies of those files. Google-native Sheets must first be exported as `.xlsx`. The source spreadsheets appear to be mostly **chord grids**, not full song lyrics; lyrics that are absent from the source cannot be generated by the converter.

## Update your existing GitHub repository
1. Back up your existing repo and Firestore rules.
2. Replace `public/index.html` with this file. Keep your existing icons, `sw.js`, and `manifest.webmanifest`.
3. Replace `firestore.rules` and `firebase.json` at repository root **after reviewing**. Rules use `adminRequests`, matching this site's actual code.
4. On your Windows PC, in the extracted repo root, run `firebase.cmd deploy --only hosting`.
5. Publish rules separately: `firebase.cmd deploy --only firestore:rules` or paste `firestore.rules` into Firebase Console > Firestore > Rules and Publish.
6. Test viewer read, admin edit, admin request, Super Admin approval, and non-admin denial.

## Prepare the Excel files
1. In Google Drive, select the files in your chord-chart folder and Download; extract the resulting ZIP into a local folder, e.g. `C:\\Users\\You\\Downloads\\chord-excels`.
2. Export Google-native Sheets as `.xlsx` separately if desired.
3. In PowerShell/CMD, navigate to `import-tools` and run:
   `py convert_drive_excels.py "C:\\Users\\You\\Downloads\\chord-excels"`
   If `py` is unavailable, use `python` instead.
4. Inspect `conversion-report.txt` and `songs-import.json`. Check the SOURCE key, sections, chord order, chord counts, and lyrics/notes for each song. Some spreadsheets have complex layouts; manual correction is expected.
5. Open the live website and sign in as Admin. Choose **I-import mula sa Excel/JSON**, select `songs-import.json`, then import. Duplicate song titles are skipped (case-insensitive normalized title).
6. Verify imported songs on another browser without logging in.

## Data format
`[{"title":"Example","key":"E","sections":[{"name":"Verse","lyrics":"Optional original lyrics","rows":[{"cells":[{"count":"4","chord":"E"},{"count":"4","chord":"A"}]}]}]}]`

## Notes
- Hosting deployment does not automatically publish Firestore rules.
- Do not enable public write access.
- Import currently writes sequentially; it is not atomic. Check success/skip/fail counts.
- Duplicate check uses title, not source file checksum. Songs with different titles may still duplicate.
- Viewer transpose remains local and does not overwrite original chords.
- Existing Firebase songs are preserved; importer adds only new songs.
